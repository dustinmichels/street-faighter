# TODO — Step 1: Basic single-player fighter

Goal: a minimal 2D-looking (pixel art) fighting game driven by real 3D models. Player controls fighter 1; fighter 2 stands idle. No multiplayer.

Design constraints carried forward from `notes.md` so later steps don't require rework:

- Characters are `.glb` files loaded at runtime with `GLTFDocument`, not editor-imported scenes.
- One fixed skeleton with fixed bone names; all animations live in the game, applied by bone name.
- Bodies are rigid parts parented to bones (no weight painting).
- Hitboxes and hurtboxes are standard shapes set by the game, never taken from the mesh.

Verified: sub-pixel camera moves render identically, a 1 px move is an exact 1 px image shift.

## 6. Animations

Authored once against the template skeleton and stored in the game, not in character files.

- [x] Idle
  - `animations/build_base.gd` holds every clip as pose tables (Euler degrees relative to rest, per-bone local axes; `.R` written via `_m()` mirror) and `build_library()`. `STANCE` = guard pose (left foot forward, fists up, hips −0.07 m); `idle` is a 1 s cubic loop breathing bob. Rest rotations come from `default.glb`. Every clip keys all 17 bone rotations + hips position, so no bone leaks between clips.
- [x] Walk (loop; used for both directions, or separate forward/back)
  - One `walk` clip (0.8 s cubic loop, guarded shuffle: front foot steps, back foot follows; planted feet stay within ~1 cm of the floor). Walk back = play it backwards (`play_backwards` / negative speed).
- [x] Jump (takeoff, airborne, land)
  - Three non-looping clips: `jump_start` (0.15 s: crouch, spring onto toes; give the body upward velocity when it ends), `jump_air` (0.25 s into a knee tuck, then holds), `jump_land` (0.2 s: crouch squash back to `STANCE`, so idle follows seamlessly). Shared poses `CROUCH`/`EXTENDED`/`TUCK`. A finished non-looping clip holds its last frame (verified).
- [x] Punch (startup, active, recovery)
  - `punch` (right straight, linear keys, 20 frames @60 fps: 5 startup / 3 active / 12 recovery; ends in `STANCE`). Times are consts `PUNCH_ACTIVE_START/END/LENGTH` and clip markers `active_start`/`active_end` (use for the §8 hitbox). Verified: fist reaches 0.65 m forward (0.20 in stance) on active frames, feet stay planted.
- [x] Fall over / knockdown

Ends flat on the back, hips 0.8 m behind the start (−Z in model space, i.e. away from the opponent), so gameplay shouldn't also slide the body that far. Verified by a 60 fps sweep: no part dips more than 2 cm below the floor.
- [x] Put the animations in an `AnimationLibrary` (`animations/base.res`) whose tracks target bones by name.

Clips: `idle`, `walk`, `jump_start`, `jump_air`, `jump_land`, `punch`, `knockdown`; tracks are `Skeleton3D:<bone>`, so the `AnimationPlayer` must sit beside the `Skeleton3D` (default `root_node = ".."`).
- [x] At runtime, add an `AnimationPlayer` to each loaded character and attach the shared library.
  - `Fighter.set_character` creates `anim` (`AnimationPlayer`, a sibling of the `Skeleton3D`, i.e. `Visual/<model>/Armature/AnimationPlayer`), adds `Fighter.ANIMATIONS` (preloaded `base.res`) as the default library (`anim.play(&"punch")`), and starts `idle`. - [x] Verify the same library plays correctly on a second model with the same skeleton.

Blue model's knockdown also rendered and keeps the floor clearance.

## 7. Fighter controller

- [x] `Fighter` scene: `CharacterBody3D` with a standard capsule collision shape, movement locked to the side (X) axis.
  - `Collision`: capsule r=0.3, h=1.8, centered at y=0.9 (feet at the body origin). Body is collision layer 2 / mask 1: it hits world geometry (layer 1) but not the other fighter (§8 does push-apart). `_physics_process` zeroes `velocity.z` before `move_and_slide()` and `position.z` after (fighters must stay direct children of an origin-aligned `World`).
- [x] State machine: `idle`, `walk`, `jump`, `punch`, `hit`, `knocked_down`.
  - `Fighter.State` enum + `state`/`state_time`; switch only via `change_state(s)` (resets timer, plays the state's clip). `hit` plays only the recoil (`knockdown` 0–0.1 s via `play_section`) and returns to idle after `HIT_STUN` (0.3 s); `knocked_down` is terminal. §8 entry points: `take_hit()` (ignored when down) and `knock_down()`. `AnimationPlayer` runs on the physics tick (`ANIMATION_CALLBACK_MODE_PROCESS_PHYSICS`).
- [x] Walk left/right at a fixed speed.
  - `WALK_SPEED` 2 m/s (input sign only, so analog doesn't change speed); `_ground_move(dir)` drives idle↔walk, `move_dir` holds the walk direction. Walk clip plays backwards when `move_dir * facing < 0` (`facing` ±1, set by the facing task). Each tick ends with `visual.global_position = camera.snap(global_position)` (§2 pixel snapping). Temporary `@export var controlled` (true on `Fighter1`) reads the keyboard until the input-source task replaces it.
- [x] Jump with gravity; no air control (or minimal), land back into idle.
  - `jump` state has `jump_phase` (`TAKEOFF` 0.15 s grounded → `AIR` → `LANDING` 0.2 s → idle), clips `JUMP_CLIPS`; `state_time` resets per phase. Launch `velocity = (move_dir * WALK_SPEED, JUMP_VELOCITY 8, 0)` with direction locked at the press (no air control); `GRAVITY` 25 m/s² applies in every state when off the floor. Verified: peak ≈ 1.35 m, 40 ticks airborne, reversing input mid-air changes nothing. Floor collision added early (§9 stage): `Floor/Body` `StaticBody3D` with a `WorldBoundaryShape3D` in `main.tscn`.
- [x] Punch: lock movement for the duration; can't be interrupted by input.
  - Grounded idle/walk only (punch beats jump if both pressed). `velocity.x = 0` and no input read for `PUNCH_LENGTH` (static, from the `punch` clip: 20 ticks), then idle; only `take_hit()`/`knock_down()` can cut it short. No input buffering. Verified: walk + jump + re-punch held mid-punch → zero movement, idle exactly 20 ticks later.
- [x] Fighters always face each other (mirror the model when they cross).
  - `@export var opponent: Fighter` (set both ways in `main.tscn`; a hand-written `.tscn` needs `node_paths=PackedStringArray("opponent")` on the node header or it stays null). `_update_facing()` runs in idle/walk only (a cross-up mid-jump/punch turns on return to neutral) and replays walk so forward/backward stepping follows. `_apply_facing()`: `Visual.basis = scale(facing,1,1) * rotY(90°)` — model +Z → ±X, mirrored so the same side faces the camera. Verified by render: both fighters face each other before and after walking through; toon + outline survive the mirror.
- [x] Input source abstraction (`PlayerInput` vs `IdleInput`) so fighter 2 can later be driven by network/AI without changing `Fighter`.
  - `input/input_source.gd` (`InputSource`, a `Resource`): `poll() -> int` returns the buttons held this tick as bits `LEFT|RIGHT|JUMP|PUNCH` (one byte, network-ready). `PlayerInput` reads the four actions; `IdleInput` returns 0. `Fighter.input` (`@export`, default `IdleInput`) is polled every tick, even mid-punch; `prev_buttons` turns held bits into fresh presses (holding jump/punch fires once), left+right cancels. `main.tscn` gives `Fighter1` an inline `PlayerInput` sub-resource; the temporary `controlled` flag is gone. Verified: a runtime-assigned scripted `InputSource` subclass walks and punches fighter 2 with no `Fighter` changes. A press on a tick when the action isn't allowed (e.g. airborne) is dropped, not buffered.

## 8. Combat

- [x] Hurtbox: `Area3D` with a fixed capsule on each fighter.
  - `Fighter/Hurtbox` (`Fighter.hurtbox`): shares the body's capsule (r=0.3, h=1.8, y=0.9). Physics layers named in `project.godot`: 1 `world`, 2 `fighters`, 3 `hurtboxes`. Hurtbox is layer 3 / mask 0, `monitoring = false` (only queried). Owner = `area.get_parent()`.
- [x] Hitbox: `Area3D` attached to the punching hand (or a fixed box in front), active only on the punch's active frames.
  - Fixed box: `Fighter/Hitbox` (layer 0 / mask 3 `hurtboxes`, not monitoring), box 0.3×0.3×0.6 at (0.62, 1.33) = the extended fist; `_apply_facing()` moves it to `facing * 0.62`. `is_hitbox_active()` = punch ticks 5–7 (from `PUNCH_ACTIVE_START/END`, read off the clip markers, compared in whole ticks); its `Collision.disabled` mirrors that each tick (debug view only). `hitbox_targets()` does a direct `intersect_shape` query (same-tick result, no Area signal lag; excludes own hurtbox) and returns the other `Fighter`s hit. Reach: hits while the gap between body centers is < ≈1.07 m.
- [x] On hit: apply damage, play hit reaction, short knockback, one hit per punch.
  - After `move_and_slide()`, an active, not-yet-landed hitbox calls `target.take_hit(PUNCH_DAMAGE 10, facing)` on each `hitbox_targets()` entry and sets `punch_landed` (reset on punch start). `take_hit(damage, push_dir)` (was `take_hit()`): `health -= damage` (clamped at 0; `health`/`MAX_HEALTH 100` added here for §8 health), `velocity.x = push_dir * KNOCKBACK_SPEED 3`, enters `hit`; `hit` decays it by `KNOCKBACK_FRICTION 15` → ≈0.28 m in 0.2 s, enough to leave punch range. Known: same-tick punch trades favor the fighter earlier in tree order (its hit puts the other into `hit` before that one's hitbox is checked).
- [x] Health per fighter; at 0 health play fall-over and stop accepting input.
  - `Fighter.health` (int, starts at `MAX_HEALTH` 100; 10 punches to KO). The hit that reaches 0 calls `knock_down()` instead of `hit` (no knockback; the clip carries the body back visually). `knocked_down` is terminal: input is still polled but no state reads it, and `take_hit` ignores it. No signals yet — §9 HUD can read `health`/`state` (or add a signal then). Verified: KO'd fighter stays put with all buttons mashed and isn't damaged further.
- [x] Fighters push each other apart instead of overlapping.
  - Script-side (bodies still don't collide with each other): after its own `move_and_slide()`, each fighter calls `_push_apart(opponent)`; if body centers are closer than `PUSH_DISTANCE` 0.6 (2× capsule radius), each is `_shove()`d half the overlap away (`move_and_collide`, so world geometry stops it; a blocked fighter's share goes to the other) and the opponent's visual is re-snapped (`_snap_visual()`). Effect: walking into a fighter pushes it at half speed; against a wall the walker stops. Verified with a test wall: gap never below 0.5996, pinned fighter stops at wall − radius, jump-ins don't pass through. No jump-over (peak 1.35 m < 1.8 m body).
- [x] Air kick: pressing punch (J) while airborne throws a kick.
  - `JumpPhase.KICK` (from `AIR` only, so one per jump; lasts until touchdown → `LANDING`) plays `air_kick` (28 frames: 4 startup / 12 active / 12 recovery into `TUCK`, held until landing; front leg straight, ≈30° below horizontal). Markers → `AIR_KICK_ACTIVE_START/END`. The shared hitbox is re-aimed per attack by `_start_attack(offset)` (`PUNCH_HITBOX` (0.62, 1.33), `AIR_KICK_HITBOX` (0.8, 0.55) = kicking foot; mirrored by `facing`), which also resets `attack_landed` (was `punch_landed`). `AIR_KICK_DAMAGE` 10. Verified headless: jump-in from 1.5 m, kick at tick 9 of the air phase hits on its first active tick (100→90, once), a second press mid-kick is ignored, landing → idle; render shows the extended kick and the opponent's recoil.
- [x] Block: hold K on the ground to guard.
  - New `block` action (physical K) → `InputSource.BLOCK` (16). `State.BLOCK` is entered from idle/walk while held (takes priority over punch/jump), rooted, keeps facing the opponent, and returns to idle on release. `take_hit()` while blocking a hit from the front (`push_dir != facing`) deals no damage, no stun: only a `BLOCK_PUSH_SPEED` 1.5 m/s slide (same friction, ≈0.06 m). Clip `block` (4 frames from `STANCE` into the `BLOCK` guard pose, held). Verified: a blocked punch leaves 100 health and slides the blocker 0.063 m; after releasing, the next punch hits for 10.

- [x] Sweep: punch while crouching to knock the opponent over; only a jump avoids it.
